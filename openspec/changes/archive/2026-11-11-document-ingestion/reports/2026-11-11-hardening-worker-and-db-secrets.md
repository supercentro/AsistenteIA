# Hardening before group 16: secrets of the worker and of the database container

Branch `feature/document-ingestion`, starting at `1e0eac0`. Authorised by the user (alternative B plus the PostgreSQL service). No group after 15 was run; migration `0005` was not applied to the development database; no dependency was changed.

## Analysis
- The worker reads: `DATABASE_URL`, `DB_CONNECT_TIMEOUT_SECONDS`, `LOG_LEVEL`, the worker and idle-in-transaction timeouts, the ingestion limits, the PDF child limits and the embedder settings. It never reads anything about JWT, CORS, privacy, rate limits or uploads.
- `JWT_SECRET` was a mandatory field of `Settings`, so the worker could not start without it, and the Compose `worker` and `db` services both received the whole `backend/.env` through `env_file` (the database container saw `JWT_SECRET` and every API setting; the API saw `POSTGRES_PASSWORD`).
- No leak to logs, images or versioned configuration was found: `.env` and `.env.*` are git-ignored and in `.dockerignore`, `JWT_SECRET` is a `SecretStr`, and the worker logs only identifiers and codes. The problem was least privilege, not disclosure.
- Side finding: `alembic` and `python -m app.cli` also call `load_settings()`, so they need the API settings. They run in the `backend` container (the guide now says so). Not changed.

## Configuration before and after
| Service | Before | After |
|---|---|---|
| `backend` (API) | `backend/.env` (everything) | `backend/.env`: API settings only (`.env.example` no longer lists worker-only variables or `POSTGRES_*`) |
| `worker` | `backend/.env` (everything, with the JWT secret) | `backend/.env.worker` (from `.env.worker.example`): the 21 `WorkerSettings` variables, no JWT, CORS or HTTP setting |
| `db` | `backend/.env` (everything) | `backend/.env.db` (from `.env.db.example`): `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` |

Code: `app/core/config.py` now has `WorkerSettings` (database, ingestion, PDF child, embedder, logs) and `Settings(WorkerSettings)` (JWT, privacy, rate limits, CORS, upload and admission limits, API statement timeout). `JWT_SECRET` is still a required field with the same validator in the API; no default was added to any secret. The two cross-field checks were split by owner: embedder and deadline/lease rules stay with the worker, CORS and upload rules with the API. `load_worker_settings()` reads `.env.worker`; `load_settings()` still reads `.env`; both raise the same `ConfigurationError` naming variables only. `app.worker`, `rag.embedder`, `rag.loaders` and `services.ingestion_service` are typed with `WorkerSettings`; the API code is untouched, so its contract and behaviour are unchanged. `.gitignore` gains `!.env.*.example` (the two new examples must be tracked; the real files stay ignored). The Compose limits (4 CPUs, 2 GiB), the offline model and the command `python -m app.worker` are unchanged. `DATABASE_URL` lives in two files by design; the example files and the guide document the drift risk.
