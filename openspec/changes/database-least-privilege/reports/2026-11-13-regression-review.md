# Regression review of the existing tests (group 11, tasks 11.1 and 11.2), 2026-11-13

Scope: the tests that existed on `main` (3b312e4) and read the environment files, the test-database guard, `alembic/env.py`, the Compose file or the settings, compared with the branch `feature/database-least-privilege`. Method: (1) a mechanical inventory of the 107 files under `backend/tests` on `main` (87 of them `test_*.py`, the rest support modules; `reports/group-11/inventory.py`, output in `inventory.txt`: patterns for environment files, the guard, Alembic, Compose and settings); (2) the diff of every modified existing test; (3) a before/after count of tests, `assert` statements and `pytest.raises` per modified file (`assertion-counts.txt`; it sees `assert` statements only, so loop iterations and parametrisation were read by hand and are named below); (4) mutations that show the compensating assertions fail when the control is broken (`mutation-regression.txt`, 10 of 10 caught after an unmutated baseline, and `mutation-cli-process.txt` for the process test); (5) the suites on the final code. Where an assertion moved, the new place and the mutation that proves it are named.

What changed in the sources the tests read (`git diff main..HEAD`): `backend/.env.example` (the test variable and a comment moved out), `backend/alembic/env.py` (an online run without an explicit URL is refused; the offline fallback reads `MIGRATION_DATABASE_URL`), `backend/app/core/config.py` (new settings classes and loaders; the only removed line is the type bound of the private `_load` helper, widened from `WorkerSettings` to `BaseSettings`), `docker-compose.yml` (services `bootstrap`, `migrate` and `cli`, new dependencies), and `backend/tests/db_support.py`. `app/core/db_safety.py` is unchanged.

## 4. Open points, stated

- **GitHub Actions has not run the new workflow** (the branch is not on the remote): nothing here is remote validation.
- The gate does not block a merge until the branch protection that requires the check `privileges` exists; it is documented as a proposal and must be applied by the owner. The ordinary `backend` job excludes the 410 role-bound tests, so their coverage figure (`--cov=app`) is no longer part of that job.
- The marking of role-bound tests depends on file-name prefixes (`ROLE_BOUND_PREFIXES`); a guard test fails if a module that builds a cluster is not marked, but a differently named new module that needs one of the gate's clusters is only caught when it fails.
- Both items above are candidates for `docs/technical-debt.md` (a group 12 or later matter, not changed here).
