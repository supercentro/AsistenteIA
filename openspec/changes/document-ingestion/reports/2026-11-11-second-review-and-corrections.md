## 9. S-01 closure, final gates and third independent review

### 9.1 S-01: root cause and fix
- **Measured cause** (real tokenizer, 2 CPUs): the normaliser took 0.3 s; the chunker spent 17 to 61 s on `x` + 1,999,998 padding characters because the splitter measures characters that the tokenizer counts as zero tokens one by one. The normaliser kept whitespace, combining marks, zero-width and other format characters, private-use and unassigned code points in any number, so one 2,000,000-character piece reached the splitter. Window size does not change the cost (about 25 microseconds per character at windows of 20,000 to 1,000).
- **Fix** (`backend/app/rag/normalizer.py`): at most `MAX_NON_CONTENT_RUN = 16` consecutive characters without content are kept (plus one separator when a cut run had whitespace); letters, digits, punctuation and symbols are never touched. Contracts, 100/20, 128 tokens and 2,000 chunks unchanged; no chunking timeout added.
- **TDD:** red by import (`MAX_NON_CONTENT_RUN` missing) and red by behaviour (the `realmodel` timing tests failed against the code of `a9a489d` with 34 to 61 s against a 5 s bound); green after.
- **Before and after** (seconds, normalisation plus chunking): zero width space 34.2 to 0.57; word joiner 60.1 to 0.45; joiner 36.0 to 0.49; combining acute 59.8 to 0.45; spaces 33.9 to 0.26; newlines 17.2 to 0.18; tabs 34.1 to 0.19; private use 61.0 to 0.52; valid Spanish prose 229,000 characters 0.49 to 0.41 (895 chunks, unchanged).
- **Mutation testing** (sequential, the original restored after each run and its hash checked): 14 valid mutants and 3 more for the third review (cap 15, cap 17, symbols counted as non-content), all killed. One mutant of the first list ("the final separator is lost") was equivalent, because the caller strips a trailing separator, so that dead code was removed; one survived the first pass and a test was added; one harness error (output decoding) was fixed and the mutant repeated.
