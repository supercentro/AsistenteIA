# Proposal

## Why

Teachers cannot yet give the assistant any material: the tables for documents and chunks and the actor-scoped search exist (change 5), but nothing can fill them. Without ingestion no later feature has data to retrieve (7 `teacher-material-ui` lists and uploads, 9 `rag-chat` answers from chunks). Ingestion handles files from teachers that must be treated as untrusted, runs CPU- and memory-heavy work (PDF parsing and embedding inference) and must survive restarts, so it needs a deliberate design instead of a request-bound background task.

The scope is defined by the contract that already exists (`docs/api-spec.yml`, tag Documents; user story 1 of `readme.md`; `docs/backend-standards.md`, section "Ingestion") plus the decisions D1 to D10 and the additional decisions approved by the user for this change (recorded in `design.md`). `readme.md` has no ticket for this change.

## What Changes

- Three endpoints of the existing contract, all scoped to the owning teacher: `POST /subjects/{id}/documents` (multipart, returns `202`), `GET /subjects/{id}/documents` (status polling) and `DELETE /subjects/{id}/documents/{doc_id}` (physical deletion with cascade).
- A **persistent job queue in PostgreSQL** and a **separate worker process** (own Compose service, same image): the upload commits the document row, the job row and the temporary file contents in one transaction before `202` is returned; the worker claims jobs with leases (`FOR UPDATE SKIP LOCKED`), renews them, recovers from restarts and fences stale workers so a document is never processed twice at the same time.
- Temporary storage of the uploaded bytes **inside the job row** (`bytea`, at most the upload limit), cleared when the document reaches `ready` or `failed` and removed with the document on deletion. Original files are never kept permanently.
- Processing pipeline in the worker: PDF text extraction in an **isolated child process** (timeout, memory and CPU limits, no shared state), strict UTF-8 for text and Markdown (Markdown is stored as text, never rendered), normalisation of control, NUL, bidirectional and Unicode blank characters (TD-027), chunking measured in tokens of the embedding model (size 100, overlap 20, hard limit 128, with a runtime guard against silent truncation), embeddings in batches, validation with the existing `validate_embedding`, and one transaction that inserts the chunks and marks the document `ready`.
- Limits and quotas (TD-023): 10 MB per file measured on the bytes actually received, 300 pages per PDF, 2,000 chunks per document, 50 documents per subject, a bounded queue depth and a bound on pending bytes (the last three are hard limits taken under locks and tested under concurrency), an expiry for jobs that wait too long, and an upload rate limit. No database transaction or lock is held while a file is parsed or embedded. Stable `error_code` values for failed documents, with fixed safe messages.
- A local, real embedding model (`paraphrase-multilingual-MiniLM-L12-v2` at a fixed revision, 384 dimensions, CPU, no network at runtime) behind an `Embedder` interface that change 9 will reuse; the number of `torch` threads follows the effective CPU quota (`EMBEDDING_THREADS`); a fake embedder exists only for tests and controlled environments and is never a silent fallback. The model is approved for the MVP; its quality on real course material is evaluated again in change 12.
- Migration `0005` (with `downgrade`): table `ingestion_jobs` and column `documents.error_code`. Migration `0004` is not edited.
- `docs/api-spec.yml` is updated additively (new responses `401`, `409`, `422`, `429`, `503`; `Document.error_code`; `required` list for `Document`) and the generated frontend types are regenerated so the CI check keeps passing. `408` is documented for clients that stay connected (the spike confirmed that a real server delivers it); nothing is promised when the client has already closed the connection. Malformed multipart requests, a missing file, unexpected fields and oversized files get distinct, controlled answers. No user interface is built.
- An isolated compatibility, safety and performance **spike** (group 1, executed and approved on 2026-11-08; reports in `reports/`) decided the open numbers (image sizes, reproducible model download and offline run, CPU and memory, a calibrated Spanish retrieval evaluation, `pypdf` version, resource limits, `bytea` behaviour including WAL, multipart limits and the `408` behaviour). The approved values are in `design.md`, section "Spike results and approved values".
- Documentation (`docs/data-model.md`, `docs/backend-standards.md`, `docs/development_guide.md`, `docs/technical-debt.md`, `docs/lessons-learned.md` if the review yields a lesson), the independent adversarial review, TDD evidence and the AI usage record from the first group.

Out of scope (confirmed by the user): any user interface (change 7), chat, RAG, conversations and personal-data erasure (changes 8, 9 and 11), permanent storage of original files, a reprocess endpoint (the teacher uploads the file again), changes to indexes, the search strategy or HNSW parameters (change 12), and Moodle or other integrations.

**BREAKING**: none. Every API change is additive and existing tables are only extended.

## Capabilities

### New Capabilities
- `document-management`: the HTTP behaviour for teachers: upload with validation (filename, extension, sniffed content, size while streaming), `202` only after the work is durable, status polling, deletion (including during processing), ownership and role rules, quotas under concurrency, the error contract and rate limiting.
- `document-ingestion`: the background processing of an accepted document: persistent queue, leases, recovery after restarts, mutual exclusion between workers, isolated PDF extraction, normalisation, token-based chunking, atomic persistence, document states and error codes, cleanup of temporary bytes and no leakage in logs or errors.
- `text-embedding`: the embedding component: the local model and its 384-dimension contract, fail-fast loading, batch embedding, compatibility of every vector with `validate_embedding`, and the rule that a fake embedder is never a fallback.

### Modified Capabilities
- `document-storage`: adds the persisted model of the job queue (`ingestion_jobs`), the stable `documents.error_code` and its constraint, and the reversibility and cascade rules of migration `0005`. Existing requirements are unchanged.

## Impact

- **Authorization / data isolation**: every document read, list, delete and upload is scoped by subject and by the acting teacher in the repository layer; a student receives `403`, another teacher or an unknown subject `404` (same response). The worker has no actor and no unscoped read: its writes take the subject from the document row and the composite foreign key keeps chunks consistent. Chunks of a document become searchable only when the document is `ready`, in one transaction.
- **Personal data (GDPR)**: documents are course material; filenames and contents can still contain personal data, so they are never logged, never returned in errors and never kept after processing (only the extracted chunks remain, as designed). The temporary bytes live in the database until the terminal state and are covered by the same cascades as the document, so the erasure of change 11 inherits them. Deleting or nulling a `bytea` does not erase it at once: copies can remain in dead tuples until vacuum, in the write-ahead log and in backups made meanwhile. This is documented as accepted debt, and the size, queue and pending-byte limits bound how much can be exposed.
- **External services**: none. Embeddings are computed locally; no document text is sent to Gemini or any other service. The model is downloaded at image build or by an explicit step, never at runtime by surprise.
- **Dependencies** (versions pinned by the spike, `uv.lock` committed): `python-multipart` (upload parsing; it also decides the multipart limits), `pypdf`, `sentence-transformers` with CPU `torch`, `langchain-text-splitters`. Versions selected by the spike (installed together on Python 3.12 and audited with `pip-audit`): `pypdf` 7.0.0 as the selected candidate (a major published on 2026-11-06; 6.21.4 behaved identically and is the fallback), `python-multipart` 0.0.33, `sentence-transformers` 6.2.0, `langchain-text-splitters` 1.1.3, `torch` 2.15.0 from the CPU index on Linux. Versions, advisories and compatibility are verified again when the dependencies are added to the project (group 2), because part of the spike reading came from summaries and the advisory data lags.
- **Code**: `backend/app/{api,services,repositories,models,rag,core}`, a worker entry point, `backend/alembic/versions/0005_*`, `backend/pyproject.toml`/`uv.lock`, `backend/Dockerfile`, `docker-compose.yml`, `.github/workflows/ci.yml`, `.env.example` and backend tests; generated types in the frontend only (no UI code).
- **Docs**: `docs/api-spec.yml` and `docs/data-model.md` change (see above); `docs/backend-standards.md` (ingestion section and temporary storage), `docs/development_guide.md` (worker, model, limits), `docs/technical-debt.md` (TD-023 and TD-027 resolved; new items proposed in `design.md`).
- **Technical debt touched**: TD-023 (quotas and `statement_timeout`), TD-024 (fixed 384 dimensions checked at start), TD-027 (blank-looking content normalised before the database); TD-022, TD-025 and TD-026 stay for change 12.
- **Dependent changes**: 7 `teacher-material-ui` consumes the three endpoints, the polling and the `error_code` values; 9 `rag-chat` reuses the `Embedder` for the question (it must decide whether to load the model in the API process); 11 `personal-data-erasure` inherits the cascades; 12 uses the data produced here to evaluate indexes and plans and re-evaluates the embedding model on real educational material (the spike corpus was written by the assistant and is small); 13 inherits the worker service, the model volume or layer and the memory settings.
