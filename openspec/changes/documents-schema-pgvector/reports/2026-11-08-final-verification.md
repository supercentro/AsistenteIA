## Reconciliation of the artifacts with the implementation
- **Migration `0004`, models, repository:** tables, composite FK `(document_id, subject_id)` to `documents(id, subject_id)`, checks (including `vector_norm` between `1e-6` and `1e6`), b-tree indexes and the hnsw index (`m=16`, `ef_construction=64`) agree with `docs/data-model.md`, the `document-storage` spec and the live catalog (tests read the catalog; `alembic check` clean).
- **`find_similar`:** authorization inside the SQL for both branches including the stored role (F7); ready-only; ordered by distance then chunk id; `top_k` 1 to 50; an unknown subject, an unauthorized actor or an unknown role return an empty list; `subject_id` and `actor.user_id` must be UUIDs (F8); the embedding must be 384 finite numbers whose single-precision norm is inside the range with a `1e-12` relative margin (F5), and the vector the helper returns is what is bound. Spec `chunk-retrieval`, design D8 and divergence 7, `docs/backend-standards.md`, `docs/data-model.md` and `docs/technical-debt.md` (TD-024) say the same.
